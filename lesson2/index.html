01

One message, two schemes

Caesar shifts letters. The ECC-based hybrid establishes a secret and uses authenticated symmetric encryption.

Preparing the default experiment…

Caesar · deterministic

Letter substitution

c = (p + s) mod 26; p = (c − s) mod 26. ASCII A–Z and a–z rotate; case, punctuation, digits and all other characters are preserved. Shift 0 is the identity.

ECC hybrid · randomized

Ciphertext + authentication tag

Hex is an encoding of encrypted bytes, not another cipher. The last 16 bytes are the GCM tag. A fresh ephemeral key, 32-byte salt and 12-byte IV are generated for every encryption.

Inspect the public ECC packet

Everything here may be transmitted publicly. Neither the recipient private key nor the ephemeral private key is exported.

Follow the hybrid algorithm and key roles
  1. Recipient: chooses the toy secret d and publishes Q = dG on secp256k1. Its prime field is p = 2²⁵⁶ − 2³² − 977; y² = x³ + 7 mod p. G is the standard generator, not (1,5).
  2. Sender: samples a fresh full-range scalar r ∈ [1,n−1], publishes R = rG, and computes S = rQ. The recipient independently computes S = dR. Neither side needs the other side’s private scalar.
  3. Derivation: the 32-byte x-coordinate of S is input to HKDF-SHA-256 with a fresh salt. The protocol version, Q, R, salt and IV form a canonical JSON-array header used as HKDF context. The output is an AES-256 key.
  4. Encryption: AES-GCM encrypts UTF-8 message bytes using a 96-bit IV, the header as additional authenticated data and a 128-bit tag. Decryption must verify the tag before displaying plaintext.
  5. Encoding: public points use SEC1 compressed form; binary fields are hexadecimal in a JSON packet. The tag detects modification under the derived key. This protocol has no sender signature or sender authentication: anyone can encrypt to the public key.
ECDH is key agreement; it does not directly encrypt text. This explicitly defined teaching hybrid is not a claim of compatibility with a standardized ECIES format or Ethereum transaction encryption. ethers 6.15.0 supplies secp256k1; the browser’s native Web Crypto supplies HKDF and AES-GCM.

Entropy estimates from short messages are biased downward: even ideal random bytes will not necessarily reach 8 bits per byte in this sample. Balanced bits or a flat histogram do not prove unpredictability, integrity or a large key space. Caesar’s unchanged nonletters leak additional structure. 03
Let language rank the keys
Try every shift, compare its decrypted letter counts with an independently estimated English distribution, and rank the candidates.


Reference corpus: built-in English or your own text
A custom corpus changes both candidate ranking and the length experiment. The built-in evaluation text is English; using another language as its reference deliberately tests a mismatched model.
RankShiftχ² score ↓Decrypted preview


For candidate s, Oᵢ is the decrypted count of letter i, Eᵢ = Npᵢ, and score = Σᵢ (Oᵢ−Eᵢ)²/Eᵢ. The smallest score wins. Add-one smoothing is applied to reference counts. This is a ranking heuristic, not a significance test or a confidence probability; small expected counts and dependent language letters violate simple χ² test assumptions. All 26 candidates are searched exhaustively; language statistics decide which is plausible. No known plaintext or true shift is given to the ranker.


Does more text help?
Reference: Jane Austen’s Pride and Prejudice. Evaluation: Lewis Carroll’s Alice’s Adventures in Wonderland. Samples contain only A–Z letters. They never overlap within a run and are not taken from the reference book.
Run the experiment to measure recovery rates.

A seeded linear congruential generator shuffles the sample-length schedule and assigns uniformly selected shifts 0–25. It is for reproducibility, not key security. Disjoint consecutive windows are drawn from a 95,000-letter held-out extract. Reported rates describe this book and sample plan, not every English message. Longer text generally improves estimation; particular short samples, names, unusual topics and a wrong language model can defeat frequency scoring. Increasing length does not guarantee that each measured rate rises.


04
Search a deliberately tiny secret
The attacker receives only Q and the public packet. Ciphertext letter frequencies are not used.
The search starts at G and repeatedly adds G. At step j, compare jG with the recipient public point Q. A match recovers d, then the attacker derives the shared secret from R and decrypts the stored packet.
Ready to search the current public key.
The bound may exclude the target key; “not found” only rules out the searched interval. Elapsed time includes browser scheduling and point operations, so it depends on the device and is not a cryptographic benchmark. Cancellation yields between batches of 32 candidates.


Small key space
B = 4,096 → at most 12 secret bits
If d is uniform on 1…B, sequential search takes (B+1)/2 candidates on average and B in the worst case. A manually chosen key may be even more predictable. A secure AES key size does not fix this bottleneck.
Properly configured secp256k1
A private scalar is uniform on 1…n−1, where n is the standard group order, approximately 2²⁵⁶. Direct enumeration is infeasible. Generic discrete-log methods such as Pollard rho take on the order of √n ≈ 2¹²⁸ group operations; they are different from this linear search.
Known bounded intervals also admit faster attacks than linear enumeration, such as Pollard kangaroo. Here linear search is used to make the weakness visible. A huge key space is essential, but protocol design and implementation still matter.


05
Explain the difference
Both attacks recover a secret, but their evidence and failure modes differ.
PropertyCaesarThis ECC hybrid
Key rolesOne shared shift encrypts and decrypts.Recipient d is secret; Q is public. Ephemeral r establishes a per-message shared secret. AES uses a derived symmetric key.
Encryption / decryptionAdd / subtract shift modulo 26.ECDH → HKDF → AES-GCM; recipient repeats derivation and verifies the tag.
Key space26 shifts including identity; about 4.70 bits if uniform.Toy recipient: 4,096 scalars, at most 12 bits. Full-range secp256k1: roughly 256-bit scalar space.
Statistical structureLetter counts are permuted; entropy is preserved. Nonletters and positions remain visible.AES body should hide plaintext letter patterns; size and public metadata still leak. Random-looking bytes do not establish security.
Attack implementedEnumerate all shifts, score decrypted language frequencies.Enumerate bounded scalars, match public points exactly, then decrypt. No language corpus required.
What can fail?Wrong corpus, short or atypical text can mis-rank the true shift. Exhaustive candidates still include it.A bound excluding d returns no match. Sufficiently large uniformly random keys make enumeration impractical.
IntegrityNone: edits are undetected.GCM detects changes under its key. No sender authentication; recovering d allows decryption and new valid ciphertext creation.


Statistical resemblance to random data is a useful observation, not the definition of a one-way function. Public-key security rests on computational assumptions and correct key generation. Avalanche measurements are mainly a hash/block-cipher diagnostic; a Caesar shift or an encoding of curve coordinates should not be judged by a hash-function checklist. This exercise does not demonstrate a weakness in secp256k1: it demonstrates a deliberately weak choice of secret range.
