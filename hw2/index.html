02

Different tools. Different jobs.

The pipeline combines key management, an algebraic key relationship, a hash and an error-detection convention.

01 / Key generation

Create the initial secret

Sample unpredictable entropy from a cryptographically secure random generator. The public test phrases above have no secrecy. A deterministic derivation cannot repair weak initial randomness.

02 / Key derivation

Reproduce and organize secrets

BIP-39 stretches a mnemonic and optional passphrase into a seed. BIP-32 derives a tree of extended keys; BIP-44 assigns standard paths within it. Repeating the same inputs reproduces the same keys.

03 / Public-key cryptography

Separate signing from verification

secp256k1 links a private scalar to a public point. Ethereum EOA transactions use ECDSA signatures. Scalar multiplication preserves group structure and is not a general-purpose hash.

04 / Hashing

Compute a fixed-length digest

Keccak-256 produces a 256-bit digest; the address uses its final 160 bits. SHA-256 supplies the mnemonic checksum, while SHA-512 operates inside HMAC for BIP-39 and BIP-32.

05 / Checksums

Detect transcription errors

EIP-55 hashes the lowercase hexadecimal address as ASCII text, excluding 0x. Each a–f letter is uppercase if its corresponding hash nibble is at least 8. This detects many errors; it does not authenticate an owner.

06 / Encoding

Change the representation

Mnemonic words and hexadecimal digits make bits readable. Encoding is reversible and provides no secrecy. BIP-39 combines an encoding with checksum redundancy; EIP-55 carries redundancy through letter case.

Why several primitives? Recoverability and account organization need deterministic derivation; signatures need a public/private key relation; address construction needs hashing; typing errors need a checksum. These requirements differ, so the system composes purpose-built techniques.
EIP-55 playground

Orange letters are uppercase checksum positions. All-lowercase or all-uppercase input is often accepted without checksum enforcement; here it is distinguished from an exact EIP-55 encoding. Some exact EIP-55 vectors themselves use only one letter case.

Keccak is not SHA3-256.

Same output length, different domain-separation/padding conventions. Ethereum address derivation requires Keccak-256.

Keccak-256 · 256 bits
SHA3-256 · 256 bits
Also compare SHA-256 and SHA-512

SHA-512 belongs to SHA-2, not to the Keccak/SHA-3 family.

A one-bit change in the hash input

Measuring…

Green squares mark changed digest bits. Exactly the least significant bit of the first input byte is flipped. For an empty message, use a single zero byte as the base input.

For ideal independent 256-bit outputs, the Hamming distance is Binomial(256, ½): mean 128, standard deviation 8. One comparison need not equal 128.

SHA-2 and SHA-3 are separate hash families. SHA-2 uses a compression-function construction; Keccak/SHA-3 uses a sponge around a permutation. Keccak was selected in the SHA-3 competition, but Ethereum’s Keccak-256 differs from standardized SHA3-256. Substituting one for the other changes the address.

Entropy is not output length

A 12-word mnemonic starts with 128 entropy bits. Its checksum adds redundancy, not independent uncertainty. A deterministic 512-bit seed does not create 512 bits of entropy from that input. An optional unpredictable passphrase can contribute additional uncertainty.

Point constraints versus hash diffusion

Public keys lie on a curve; their two coordinates are not independent arbitrary strings. Hash outputs are designed to diffuse changes and behave pseudorandomly. Derivation should also hide useful relationships from an observer without the seed.

What the numbers can establish

Frequencies and Hamming distances can reveal conspicuous biases or implementation mistakes. Balanced outputs and high empirical entropy cannot establish preimage resistance, collision resistance or secure key generation. Determinism also means low correlation is not statistical independence.

Checksum probabilities

With a 4-bit BIP-39 checksum, 1/16 of arbitrary 12-word index sequences pass. Under EIP-55’s idealized model, a random case pattern matches with probability 2⁻ᴸ for a fixed address with L letters; averaging over uniform hexadecimal addresses gives (13/16)⁴⁰ ≈ 0.0247%. Neither checksum proves ownership.

05

Decades of building blocks.

These technologies were developed at different times, for different purposes, and later combined in wallet software.

1977

RSA

Public-key scheme introduced; the journal paper followed in 1978. RSA is historical context here, not an Ethereum wallet step.

2001–02

SHA-2 / SHA-512

Introduced in 2001; FIPS 180-2 standardized SHA-512 in 2002. Used inside HMAC in the wallet pipeline.

2012

BIP-32

Hierarchical deterministic keys from one seed.

2013

BIP-39

Mnemonic representation and deterministic seed derivation.

2014

BIP-44

Standard paths for multi-account, multi-coin HD wallets.

2015

SHA-3

NIST FIPS 202 standardizes the Keccak-based family; Ethereum uses pre-standard Keccak-256.

2016

EIP-55

Mixed-case checksum encoding for Ethereum addresses.

Elliptic-curve cryptography predates the wallet BIPs. secp256k1 is specified in SEC 2 (2000; version 2.0 in 2010). The assignment’s “2001” date for SHA-2 refers to its introduction; the final FIPS 180-2 publication is dated August 2002.

Scope, implementation and reproducibility

The page runs offline computations in HTML, CSS and JavaScript. ethers 6.15.0 supplies BIP-39/BIP-32, secp256k1, Keccak-256 and EIP-55; js-sha3 0.9.3 supplies SHA3-256. Both libraries are vendored locally with their licenses, so there is no CDN dependency. No wallet provider, blockchain request or transaction is involved. The interface, statistical measurements and discussion are implemented for this coursework. It would be misleading to claim that these standard primitives were implemented from scratch.

Hash-only experiments use arbitrary byte strings, not mutated public keys presented as valid wallets. Address-frequency experiments derive actual secp256k1 keys through BIP-32. Re-run with the same phrase, passphrase, indices and N to reproduce the data. Hex entropy is −Σpᵢ log₂pᵢ, with maximum 4 bits per hex digit.
